# PR review corrections and regression work

The September 10 review of PR #10974 identified gaps outside the earlier validator-focused test ledger. The previous blanket claims of complete coverage, a fully green integration suite and uniformly low residual risk are superseded by this ledger. Passing a manifest validator is not evidence that store approval, host input admission or a real sandboxed worker enforces the same boundary.

The peer-retry test uses real channels with injected authentication outcomes; it does not claim a hostile-UID service integration test. GPU render-node driver exposure and the private Smithay Wayland parser remain attack surfaces, not covered by a claim that plugins receive only safe pixels.

## Still open

Default native payload distribution and installed acceptance remain release gates. Failed asynchronous activation can still leave persisted enable/placement intent; transactional recovery needs a separate lifecycle change and regression. An explicitly trusted local-install workflow must remain distinct from registry distribution; registry provenance must not be inferred from downloaded manifests. These open items prevent this ledger from being a completed audit or merge-readiness assertion.
