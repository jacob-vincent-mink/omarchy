# PR review corrections and regression work

The September 10 review of PR #10974 identified gaps outside the earlier validator-focused test ledger. The previous blanket claims of complete coverage, a fully green integration suite and uniformly low residual risk are superseded by this ledger. Passing a manifest validator is not evidence that store approval, host input admission or a real sandboxed worker enforces the same boundary.

| Priority | Boundary and attack | Status and regression evidence |
| --- | --- | --- |
| Blocker | Checkout/config classification: approve before first enable, remove `sandbox`, then load QML in-process; missing/broken checkouts disappear from management | Host-owned monotonic identity added at install and native review/approval, consulted by CLI and shell even without a runtime. `plugin-review-test.sh` exercises real CLI/native approval before activation, manifest removal/corruption, runtime absence and missing-checkout removal. The offscreen Quickshell registry fixture checks trusted URL denial, changed manifest ID and discovery failure. |
| Blocker | Filesystem selection exposes approval store, signing keys, host config or runtime authority; signing failure prevents revocation from stopping work | Approval and admission now check canonical protected roots, aliases and key link counts; store and CLI tests reject read/write authority selections and old signed unsafe approvals. Revocation persists denial and stops before signing. Store tests cover missing-key denial/recovery and, with `OMARCHY_TEST_SYSTEMD=1`, verify a real service stops despite signing failure. Same-account compromise being out of scope does not justify handing its signing key to a sandboxed worker. |
| Blocker | Closed private surfaces request screen-sized pointer regions or keyboard focus outside host-owned slots | Host policy now separates rendering, pointer admission and keyboard authorization. Closed defaults remain slot-only before and after ownership; explicit visual/pointer roaming never grants keyboard focus. Qt also clips pointer delivery synchronously and cancels grabs on narrowing/dismissal. `plugin-input-test.sh` executes the policy and ownership methods. The opt-in real `shared_outputs` fixture uses an always-visible hostile worker requesting full-output input and exclusive focus: underlying host clicks/keys survive closed and visual modes; pointer roaming receives clicks without host keys. It also exercises owner transfer, hotplug, Escape, summon and restart. This supersedes the partial `security/ward-fix` formula, which still allowed closed input after prior ownership. |
| High | Exec token-root prefixes match sibling paths; mutable DATA symlinks redirect host commands outside the selected tree | Lexical root matching fixed and tested for token/absolute PATH and DATA roots and siblings. Mutable-file confinement remains open: it needs pinned/descriptor-backed consumption, not canonicalize-then-pass-the-original-path. Broad approved CLI authority remains a separately disclosed residual. |
| Release gate | Missing native payload and failed graphics activation leave confusing lifecycle state | Open; discovery now reports unavailable approval as unknown, not disabled. Revocation must not falsely claim success when management is unavailable. Default packaging and installed-VM/physical graphics acceptance remain unfinished. |
| Test gap | Generic worker fixture expects adapter-specific `OMARCHY_PATH`; two mounts reuse one consumed descriptor | Fixed fixture contract and independent descriptors. All seven worker tests passed with `OMARCHY_TEST_SYSTEMD=1` and local bubblewrap 0.12.0. Graphics, audio and proxy suites have separate opt-ins and are not covered by this result. |

Additional review work remains for worker-facing grant minimization, observation polling, Qt mouse-grab release, invalid session peers, consistent topology/buffer bounds, real decoder adversarial bytes and accurate case-level documentation. GPU render-node driver exposure and the private Smithay Wayland parser are residual attack surfaces, not covered by a claim that plugins receive only safe pixels.

The separate security-review worktree may identify additional issues. This ledger records implemented fixes and their actual evidence, not a completed audit or merge-readiness assertion.
